01 / INTRODUCTION

Give me something real enough to fail.

If I’m learning a protocol, I want to wire it up, send real messages through it, break it on purpose, and watch the system recover. That instinct has taken me from embedded test benches to security tooling, payment hardware, and tools used by community teams.

I care about the handoff as much as the build. A system is only useful if the next person can understand what happened and what to do.

02 / EMBEDDED SYSTEMSHardware bench

CAN-FD test bench

What should an actuator do when the next frame never arrives?

I built a two-STM32 bench with FreeRTOS: one controller sends temperature and RPM data over CAN-FD; the other validates identity, integrity, and freshness before controlling a fan. A Python harness captures traffic and injects delayed or dropped frames to check timeout, fail-safe, and recovery behaviour.

RF Asset Finder

How do you know a silent tag is missing rather than just late?

I built a 433 MHz tag and base station with device IDs, sequence numbers, CRC-16 checks, acknowledgements, retries, and a missing-tag timeout. Desktop tests cover corrupt frames, duplicate sequences, invalid packet types, and timeout state.

WHAT THE TRACE ASKSWhen does “late” become “unsafe”?

A real bench test is more than a green LED. I look at the timing, the decision at the boundary, and whether the system recovers cleanly afterward.

INPUT LOST / OUTPUT SAFE
01

Measure the circuit

In electrical and electronic circuits coursework, I use oscilloscopes and digital multimeters to measure signals, compare readings with expected behaviour, and work back through a schematic when the circuit disagrees with the calculation.

Oscilloscope / DMM / schematics / analog & digital circuits
02

Bring up the interface

With STM32 and Arduino projects, I connect sensors and actuators, check the data crossing each interface, and debug the path from an input reading to an output action. I have worked with CAN-FD, UART, SPI, I²C, and 433 MHz radio links.

Microcontrollers / buses / sensors / actuators
03

Test the bad day

On the CAN-FD bench, Python tests capture traffic and inject missing or delayed frames. On the RF prototype, packet tests exercise CRC failures, duplicates, retries, and timeouts. I check the recovery path as carefully as the normal path.

Fault injection / bus logging / automated checks / recovery

Current foundation: lab coursework and independently built benches. I’m continuing to develop deeper hardware validation practice.
